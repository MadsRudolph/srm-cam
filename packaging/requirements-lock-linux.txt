# PINNED build environment for the SRM-CAM AppImage - the exact package set
# verified against the full test suite on Linux. packaging/build.sh and the
# Linux half of the build workflow both install from THIS file.
#
# Produced on a real Linux machine (Arch, 2026-09-02), not by freezing on
# Windows. pip freeze resolves for the platform it runs on: a freeze taken on
# Windows against a Linux platform tag evaluates environment markers against
# the Windows host, and in practice pulled in pywin32-ctypes and a PySide6
# version that does not match this project's Windows lock at all. Nothing
# built from a freeze taken that way would be trustworthy, so this file only
# ever comes from a Linux machine that has just run the test suite against it
# - the same way packaging/requirements-lock.txt was produced on a real
# Windows machine. 918 passed.
#
# Two locks, not one file with environment markers: the Windows lock's header
# promises that a rebuild in five years produces the same app, and a
# marker-based file is only ever resolved on one platform at a time. Two files
# keep that promise on both. The cost is that upgrading a dependency means
# regenerating both.
#
# To regenerate, on a Linux box:
#   1. python3.12 -m venv .build-venv
#      .build-venv/bin/pip install -r packaging/requirements-build.txt
#   2. .build-venv/bin/pip install -e . --no-deps
#      .build-venv/bin/pip install pytest
#   3. QT_QPA_PLATFORM=offscreen GERBER2RML_GL=software \
#      .build-venv/bin/python -m pytest -q      (must pass)
#   4. .build-venv/bin/pip freeze > packaging/requirements-lock-linux.txt
#   5. re-add this header, strip the dev-only lines (pytest, pluggy,
#      iniconfig, Pygments) and the editable self-reference pip freeze writes
#      for step 2's install
#
# .github/workflows/linux-lock.yml automates the same steps on a runner, for
# whoever does not have a Linux machine to hand.
#
# Python: CPython 3.12 - matched to the Windows lock so both artifacts are
# built by the same interpreter series.
