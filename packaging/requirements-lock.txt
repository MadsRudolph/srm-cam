# PINNED build environment for SRM-CAM — the exact package set that produced
# the shipped installer. build.ps1 and the GitHub Actions build workflow both
# install from THIS file, so a rebuild in five years produces the same app
# instead of whatever PyPI happens to serve that day.
#
# Why pins matter here: packaging/requirements-build.txt declares loose ranges
# (PySide6>=6.5, shapely>=2.0, ...). Those are fine for day-to-day development,
# but an unpinned rebuild after a major PySide6 or numpy release can fail to
# build, or — worse — build fine and quietly change toolpath output.
#
# To regenerate after intentionally upgrading a dependency:
#   1. powershell -File packaging\build.ps1 -Recreate   (installs the loose set)
#   2. .build-venv\Scripts\python.exe -m pip freeze > packaging\requirements-lock.txt
#   3. strip the dev-only lines (pytest, pluggy, iniconfig, py-spy, Pygments)
#   4. run `pytest` and cut a test board before committing the new pins.
#
# Python: CPython 3.12 — the interpreter this pin set is verified against and
# what the build workflow uses. Bumping it is a deliberate step: let the
# monthly `canary` CI job (.github/workflows/tests.yml) tell you when to.
