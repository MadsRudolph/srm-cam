Hardware & firmware

An Arduino on the SRM-20's internal SPI bus = live DRO, electrical touch sensing, auto probing, click-to-jog, auto fiducial finding — and, since firmware v3, the spindle and transport controls too (Machine control).

Optional — everything else works without it

This whole page is about one convenience: automatic probing. Traces, drilling, cut-out, double-sided registration, rework, simulation and every export run on a stock SRM-20 through VPanel with nothing fitted to the machine, and Novice mode hides the machine dock — live DRO, jog, streaming, the machine test — and bed leveling with it, because probing drives the machine and STOP is in that dock. Novice keeps Corner = tool, which only reads the tool position. Bed leveling without the Arduino works in either mode — measure the grid by hand and type the heights in.

Install (one-time)

  1. Fit the Arduino Behind the SRM-20's back panel, wired to the controller's SPI header. Full wiring: docs/2026-06-25-srm20-spi-and-bed-leveling.md in the repo.
  2. Flash python scripts/flash_firmware.py — syncs the bundled library, compiles, uploads, and verifies the board came back as v3 with the patched features. --compile-only just checks the build; --port COM4 pins the port. Needs an arduino-cli (the Arduino IDE bundles one). 115200 baud.
  3. Verify, then close the Serial Monitor You should see # SRM-20 prober v3 ready. followed by the command list. The app can't open the port while the Serial Monitor holds it.
Do not flash from the Arduino IDE

The sketch includes the library with angle brackets, so the IDE resolves it from Documents\Arduino\libraries — not from this repo. If that copy is stale you get a firmware that compiles cleanly, boots, answers the version query and probes fine, but is quietly missing commands (they build as NOPATCH stubs). flash_firmware.py syncs first, every time, so the two cannot drift.

Old firmware?

If probing works but Auto fiducials or drift correction don't, reflash — one flash gets everything (v3).

Probe wiring (every session)

One clip: red (D7) → the copper board. The tool is already grounded through the collet/spindle to the machine frame. Bit touches copper → D7 pulled LOW = contact.

  • Isolate the board from the bed (paper/tape under it) — the only ground path must be the bit on copper.
  • Spindle OFF for all probing.
  • Test: touch the red clip to the bit — bit ○ fills.

How a touch is measured

  • Debounced — 3 consecutive LOW reads; stepper EMI can't fake a touch.
  • Two-stage verified — coarse 25 µm find, lift, fine 10 µm re-touch; must agree within 60 µm or the point retries → UNSTABLE.
  • Drift-corrected — periodic reference re-touch (drift chk) corrects warm-up drift.

Serial protocol (bench reference)

115200 baud, newline-terminated, microns. The app speaks it for you.

CmdMeaning
D / P id x y / BSet datum / probe point / re-touch reference (drift)
T / WTouch-off / touch-off + zero work-origin Z
H x yHole test: H 1 copper, H 0 hole
J x y / LJog (lifts first) / lift to safe Z
Q / G / VPosition+touch / work origin / version+features
C / M x y z sExperimental streaming: begin session / one move
X / S rpmFull status word / spindle on-off (the rpm value is ignored by the machine)
~ ^ % KPause / resume / stop the move / cancel the job
Y / IMove to view position (moves the head) / machine remote-protocol version
F us / N dx dy dz s / A 0|1SPI framing delay / timed relative move / status-guard toggle
!ABORT — stops the spindle, drops the move in flight, releases a pause hold, then lifts

Errors: E <id|cmd> NOTOUCH | UNSTABLE | NODATUM | ABORT | RUNAWAY | LOW | COVER | NOPATCH | NOSESSION | CMDERR | DEADMAN | NOREF | PAUSETIMEOUT. For probe points the second field is the point id; for every other command it is the command letter. Meanings in Troubleshooting.

Streaming (experimental)

Stream (exp.) sends toolpaths move-by-move over SPI — no VPanel. Every session starts as a dry run (Z held 2 mm up, can't cut); a wet run starts and stops the spindle itself, holds on Pause and aborts if the lid opens — but the spindle speed must still be set on VPanel's slider first, and the raw speed value has to be calibrated on dry runs. For real jobs, use exported .nc through VPanel. Full detail on Machine control.
