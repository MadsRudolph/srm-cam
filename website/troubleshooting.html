Troubleshooting

Symptom → cause → fix, learned on real boards. The usual path comes first: the run on the mill, then Calibrate and the etch on the laser, then the mask and the silkscreen. Search for what you saw, or pick where it went wrong.

On the mill: the run

The rows below cover Drill and cut out on a laser board and Mill it on a mill-only board. The run page itself: The mill page.

The drill and the cut-out keep stopping, and the job takes far longer

CauseThe bit sits too high in the collet, so the head has to go very low to reach the copper. The mill's Z ends at −55 mm in machine coordinates; the through-cuts of the drill and the cut-out go 2 mm below the surface and keep hitting that end.

FixWith the bit on the copper, machine Z must stay above −50. Read the Z in SRM-CAM's bottom bar: it always shows machine Z. Too low: loosen the collet and refit the bit so it sticks out further, then start the run again. (By hand in VPanel, switch its coordinates from G54 to Machine to read it, and zero Z again afterwards, back on G54.)

“The mill refused the job”

CauseVPanel's command set is not NC Code. The machine holds in pause with its error light up.

FixThe run sets the command set to NC Code by itself before it starts, whenever it can read the mill over USB, and says so in its log. If it could not: Machine › The mill's settings… shows what the mill has, with a button Set the command set to NC Code. On Windows, VPanel does the same: Setup › Command Set › NC Code, then press Cancel to clear the pause.

“The mill's G54 X/Y origin is not machine 0, 0”

CauseSomeone set a G54 X/Y origin in VPanel. Nothing has been cut: the run checks this first.

FixIn VPanel, set G54 X/Y back to machine 0, 0: in Machine Coordinate System move to X 0, Y 0, then set the G54 X/Y origin there.

“The board hangs off the stock” / “Use a bigger piece”

CauseThe board isn't on the stock outline, or it doesn't fit with 3 mm margins.

FixCheck the W and H you typed. Drag the board onto the outline, or use a bigger piece. 3 mm is the least the run accepts; a laser board wants 6 mm of waste each side for Calibrate's marks (how much sheet).

“No copper under the clicked spot” / “The probe already reads contact”

CauseThe probe has no contact with the sheet's copper (the probe bracket's tongue, or the red clip with a plain bracket), or it, its wire or the bit is touching something it shouldn't. In the bracket, it can also mean the stock isn't in the corner the page says.

FixCheck the sheet is pushed fully under the tongue (or the clip is on its copper), and the wire. Check that the bracket drawn on the bed is in the holes the real one is screwed into, see The mill page: the stock.

“The copper is … mm out of flat - more than the cut can follow”

CauseThe surface probe found the sheet more than 1.0 mm higher in one place than another. Nothing has been cut.

FixRe-tape the sheet flat (or use a flatter piece), then press Start again. Why the run levels: Why a laser board is levelled too.

“The job runs under the bracket's probe tongue … and the bit would hit it”

CausePart of the job reaches under the probe bracket's tongue at the back edge of the sheet.

FixMove the board away from that edge, or use a bigger piece: at least 12 mm longer and wider than the board, with Centre the board on the copper ticked.

“This tool profile needs 2 different bits”

CauseThe run uses the one bit in the collet for everything, and the profile on Your board asks for two (the ball-mill profile counts its 0.44 mm traces and 0.8 mm holes as two).

FixPick a one-bit profile on Your board: the 0.8 mm flat one. Or, in Pro, export the files and run them in VPanel.

The run: traces shallow in one area, even with levelling

CauseThe sheet springs under the bit. The light probe touch measures it floating; the cutter pushes it down.

FixPress on the copper there. If it gives, tape it down under the board area. Then recut in boxes at the check, or use Start at.

“The bit is touching the copper. Raise it first”

CauseThe jog pad and arrow keys don't lift, so a sideways step would drag the bit through the copper.

FixPage Up, then jog.

The arrow keys move the board, not the machine

CauseArrow keys on the jog pad isn't lit. It goes off by itself on STOP, on disconnect and when a run starts.

FixLight it again. In a box being typed in, the arrows stay with the box.

“The Roland SRM-20 printer is not installed on this PC”

CauseThe Roland driver is not installed, or it was installed with the mill plugged in too early, so Windows has no printer called Roland SRM-20. VPanel also fails to see the mill in that case.

FixOpen Control Panel › View devices and printers: the SRM-20 has to be under Printers. If it is missing or shown as Unspecified, unplug the USB cable, uninstall the driver, restart, and install it again in Roland's order, with the cable connected last. Steps and downloads: Install & connect: Roland's driver.

✕ marks on the traces: the checks say the spots will be shorted

CauseTwo nets sit closer than the method can cut: 0.8 mm for the flat mill, 0.44 mm for the ball mill. The cutter physically cannot pass between them, so the gap stays copper whatever the depth.

FixFirst check the chip at the top left: a board drawn for the laser should say Laser, and is then checked against the laser's 0.20 mm instead (see From KiCad). For a milled board: more clearance in KiCad (Set design rules for SRM-CAM, or Board Setup › Net Classes, at least 0.8 mm), or the ball mill. If the design can't change: in Pro, Isolation traces › Cutting parameters and tick Cut gaps too narrow for the bit (trims pads), which trims both pads.

Traces are shorted in some areas and clean in others

CauseThe copper foil is 0.035 mm and the cut 0.15 mm deep, while a clamped sheet bows by about 0.13 mm. Where the sheet dips, a flat cut never gets through the foil.

FixThe run levels by itself: Mill it probes the sheet before it cuts and follows the surface (The mill page). If it still happens, the sheet is springing under the bit: hold its free edges down (Holding the copper). Spots missed on a board already cut: rework them. By hand (Pro): level the bed, jog to the first marked point, set the final Z zero there, then Probe over the link; the finished probe switches on Warp the exported cut to this surface.

The board looks clean, but two nets are shorted

CauseA hair or strand of copper the mill didn't clear, lying across a channel. Burrs from the cut and the sanding do the same.

FixInspect the board closely after sanding, and check with a multimeter on continuity: every connection you want beeps, and no two nets beep. Scrape a strand out along the channel with a knife; a real uncut gap needs rework.

On the laser: Calibrate

Every message below is the laser page's own, from the report under Alignment. What a good report looks like: The report.

“The board was not found on the bed: at best a of b holes matched”

CauseThe sheet is more than about 4° off square, partly outside the camera's view, or upside down; or its holes are full of swarf.

FixLay the sheet square to the bed's edges, copper face up, the board near the middle, brush the holes out, and press Calibrate again. Dragging the drawing, as the message suggests, makes no difference: the search always covers the whole bed. See Where on the bed.

The photo shows laminate where the copper should be

CauseThe sheet is upside down. A board whose hole pattern is symmetric can be “found” that way up too, so the report alone does not catch it.

FixTurn the sheet over: copper face up, the same way up as it came off the mill. Press Calibrate again. Always look at the photo before you etch.

“The proof marks in the waste beside the board did not show in the photo”

CauseThe camera could not see the small marks: glare, or a dull or dirty patch of copper where they went.

FixPress Calibrate again. If it repeats, ask for Pro: the message's Mark passes and the marks' place are under Proof options, which Novice does not show.

“The drilled holes could not be found, so the job was not moved”

CauseThe holes read grey, not dark, in the photo: swarf or dust in them, or holes not drilled through.

FixBrush or vacuum the swarf out of the holes and press Calibrate again. Holes not through: back to the mill, The mill page.

“Only a of b holes were seen on the lock”

CauseFewer than 90 % of the holes showed when the job locked on. It did move the job; the report asks you to check.

FixZoom in on the photo: if every pad sits round its hole, etch. If not, clean the holes and Calibrate again.

“The camera's correction changed by more than 1.5 mm”

CauseThe marks landed far from where the camera expected them: the camera or the head was knocked, or this PC had an old correction.

FixCheck the drawing sits on the pads in the photo, and press Show where: the blue outline must sit on the board. If it does, etch. If not, Calibrate again.

The report says the marks went “in the isolation”

CauseThere was no copper beside the board to mark on: it was broken out of its sheet, or the sheet ends too close to it.

FixNothing to fix: the marks went on copper the etch removes anyway. Next time keep the board on its tabs with waste round it: how much sheet.

“No dot in the photo: is the lid closed and the material under the head?”

CauseAutofocus could not see the blue dot: the lid is open, the sheet is not under the head, or the photo is too bright.

FixClose the lid, check the sheet lies under the head, and press Calibrate (or Autofocus) again. Still nothing: Set the height by hand under Focus.

A board with no drilled holes

CauseCalibrate finds a board by its holes, and Align in Novice needs at least two.

FixDrag the drawing onto the copper in the photo and press Calibrate: it focuses, corrects the camera and leaves the job where you put it (No drilled holes, so the job stays where it is). Check it with Show where, then etch.

“No answer from the laser at 201.234.3.1”

CauseThe F1 Ultra is not plugged into this PC, is off, or is still starting. Over USB it shows up as a network adapter, with the laser at 201.234.3.1. The chip at the top right turns red: Laser: no answer.

FixCheck the USB cable and that the laser is on, wait for it to finish starting, and try again. No driver or xTool Creative Space is needed.

On the laser: etching the traces

The middle is clean, the edges are not through

CauseThe board sits towards the edge of the laser's field, where it is weaker, or the sheet is not flat (out of focus at its edges).

FixBox the spots in Rework and Re-etch the boxes. Next time put the board near the middle of the bed. A sheet that rocks: tape its corners down in the waste, or press Focus map before you etch. Field test… on a spare sheet tells focus from field. See Where on the bed and Focus.

A trench still shines after the etch

CauseCopper left in it: not through yet. Etched copper turns dark.

FixIf the sheet has not moved: Rework mode, a box over each spot, Re-etch the boxes. Look again and repeat. See Re-etching spots.

The laser stopped in the middle of a run

CauseSTOP or Esc was pressed, or the laser did not answer: The job did not finish within … s.

FixIf the sheet has not moved, look at the photo and finish the job: box the unfinished parts in Rework and re-etch them, or Select the trenches that need it and etch those. If the sheet moved, Calibrate first. The rail row is ticked only by a whole run.

The job lands beside the board, or mirrored

CauseThe sheet moved after Calibrate, a camera correction that is off (the report warns over 1.5 mm), or the wrong copper face for the side facing up.

FixBefore you etch, Show where runs the blue diode round the job's outline without marking. Check Copper face: B.Cu is etched mirrored, F.Cu as drawn, and the face it names must be the one facing up. Then press Calibrate again. See the report.

Fine traces burnt, or the copper not cleared anywhere

CauseCopper stock the recipe was not made on. FR4 1.6 mm · proven is measured on the lab's FR4; the other presets are uncalibrated.

FixCheck the preset is FR4 1.6 mm · proven and the stock is the lab's FR4. New stock is calibrated on a scrap with the exposure grid, in Pro: see New copper stock.

On the laser: mask and silkscreen

The mask openings are off the pads, or Align will not line it up

CauseAlign was not run for the Mask job (switching jobs keeps the old place but does not line up), the drawing was more than about 25 mm off when Align ran (Could not match the references), or the board moved.

FixAutofocus on the ink, drag the drawing close, Align again, then open three pads first and read the rims: Check on a few pads. Pads still hazy after the run: if the board has not moved, select them and open just those again.

The silkscreen is off the board, or reads backwards

CauseAlign was not run after the sheet was turned over: the job kept the traces' place, which is wrong for the other face. Text that reads backwards: Mirror left–right was ticked by hand; the Silk job is drawn as KiCad shows it, not mirrored.

FixCheck the laminate is up, Autofocus, drag the drawing close, Align, then Show where before Mark the silkscreen. See Silkscreen.

No Solder mask, Silkscreen or Paste stencil row on the rail

CauseThe Gerber folder has no mask, silkscreen or paste layer. A row only appears for a layer the folder has.

FixPlot those layers into the same folder in KiCad, or use Send to SRM-CAM, which plots them all. Then open the folder again.

Probing and the link

Connect fails

CauseThe Arduino IDE's Serial Monitor holds the port, the wrong port is picked, or the cable was replugged.

FixClose the Serial Monitor; pick the right port; replug and Machine › Rescan the serial ports. Only one program can hold the port.

A whole column of probe points failed

CauseThey were outside the machine's travel.

FixThe grid is clipped to the reachable copper when it is built; if points still fail, the job itself is off the bed: see the checks.

no touch

CauseThe probe has no contact with the copper (the tongue, or the red clip), the copper is dirty or oxidised where the bit lands, or the bit started too high above it.

FixCheck the sheet sits fully under the bracket's tongue, or reseat the red clip on the copper (it is the only wire: the bit is wired inside the machine). Clean the copper, and start the bit a couple of millimetres above the surface.

unstable

CauseA flaky contact.

FixClean the copper and reseat the sheet under the tongue (or the clip), then probe the failed points again.

“The bit is already touching the copper”

CauseBoth touches descend from where the bit is, so they cannot start on the copper.

FixRaise it a few millimetres with Page Up, then try again.

“No live position yet”

CauseThe grid is measured from where the tool is standing, so the position readout has to be alive first.

FixGive it a moment after connecting, and try again.

A lone spike in the 3D surface

CauseA flaky touch at that point.

FixClear that row and probe it again.

Nothing moves after a STOP

CauseSTOP drops the move in flight and stops the spindle; the bit stays where it is.

FixRaise the bit with Page Up before the next move.

Linux: “permission denied” on the port or the mill

CauseLinux lets only root open the Arduino's port and the mill's USB until a rule says otherwise.

FixMachine › Set up USB access… once, with your password. If a cable was in while it ran and still refuses, unplug it and plug it back in.

Panels

“Two boards overlap” and the export refuses

CauseOverlapping boards are one shape and cannot be cut apart.

FixMove one, or Set up the job › Where it sits on the bed › Lay them side by side (4 mm apart) or Butt them together (one shared cut).

A board's side is not in the cut-out

CauseIts edge is on the sheet's edge, so there is nothing to cut there.

FixIf that is wrong, set the sheet's real size and corner on Set up the job › The copper.

The panel does not fit the reachable copper / “do not fit on the sheet”

CauseThe sheet ends before the travel does, or the boards plus their gaps need more copper than the sheet has. Lay them side by side already starts a new row when a board would run past the sheet; this message means the rows don't fit either.

FixMove the sheet, butt the boards, use a bigger sheet, or take a board off and cut it another time.

Double-sided by hand

Top mirrored or offset after the flip

CauseThe board was turned the other way than the plan expects. A fiducial fit cannot catch this.

FixBefore cutting the top, select the top step and jog to a distinctive board hole to check. See Double-sided boards.

“Too far out to cut”

CauseThe measured board is too far from where the plan put it.

FixRe-seat the board and probe again; Find it for me is repeatable. The files are not written under a bad fit without asking.

Setups and the app

“Setup loaded, but … could not be read”

CauseThe Gerber folder moved, or the file is from the first interface with something this one cannot read. It says what.

FixCheck the job before you cut; point it at the folder again.

The chip at the top left says the wrong method

CauseKiCad's Set design rules for SRM-CAM was not used, so SRM-CAM guessed from the narrowest gap between two nets.

FixClick the chip and pick the right one. It changes the checks, the tool profile and the rows on the rail. See How it is made.

Can't find the exports or setups

CauseThey live in your Documents.

FixDocuments\SRM-CAM\exports and …\sessions; File › Open the export folder opens it. Dialogs reopen the last folder used.

The window never opens

CauseA startup failure, often the graphics driver.

FixRead Documents\SRM-CAM\gui2.log. On Linux without a GPU driver, run with GERBER2RML_GL=software.

By hand in VPanel (Pro)

Only when you export the files and run them in VPanel yourself: Milling a board by hand.

The cut-out ran first, and the board came loose before the traces

CauseVPanel lists the files alphabetically, so _cutout.nc lands above _drill.nc and _traces.nc, and VPanel runs the list from the top. Everything after the cut-out is machined on a board held by four 1.5 mm tabs.

FixAfter Cut › Add, look at the list before Output: move the cut-out to the bottom with the arrows. The list must start with the drill or the traces (the lab prefers the drill first), never the cut-out.

Z was set, but the job cuts air, or goes far too deep

CauseZ was set with VPanel on Machine or User. The exported files are NC code and move in G54, so they run from whatever G54 zero the last person left. Machine's origin cannot be moved at all; User is the RML origin, which NC files ignore.

FixSwitch VPanel's coordinate list to G54, lower until SRM-CAM reads Touch, and press Set Origin Point › Z. Leave X and Y at the machine origin. See Zero Z on the copper.

VPanel refuses the file with an error

CauseVPanel's command set does not match the file (.nc needs NC Code, .rml needs RML-1), or a coordinate is outside the machine's travel.

FixSet the command set in VPanel's Setup dialog. For travel, the Off the bed check names the cause; move the job fully onto the bed.

The job is not over the copper

CauseThe sheet's corner on the stage is wrong, or the board was placed off the sheet. Click to jog to the board's corners shows it before anything is cut.

FixFind the copper's corner with the probe and press Set up the job › The copper › Set the corner from the tool, then place the board on the sheet (Centre on the bed's toolbar) and export again. Never move the XY origin in VPanel instead. In Pro, the run can find the copper itself: the stock anywhere.

Wrong depth after a bit change

CauseA new bit sticks out by a different amount, so the old Z zero is wrong for it.

FixRe-zero Z after every bit change and after the flip, with VPanel on G54, and check the machine Z is still above −50. Never re-zero X or Y. The lab's 0.8 mm flat profile uses the one bit for everything, so it has no bit change.

Cut far deeper than the trace depth on a screwed-down board

CauseThe extra depth for a board held at points: a quarter of the arch the map shows, capped. With the warp off, the whole range is charged.

FixMake sure the map is applied. If it is still too much, untick Work the extra depth out from the probe map and set Cut deeper by yourself, on Set up the job › The copper. See Holding the copper.

Still stuck?

Ask Mads Rudolph or the course TAs, or open an issue with the symptom, the step you were on, and the text of the check or the message. For the laser, attach Documents/SRM-CAM/laser.log.

Stuck, or not sure? Ask in the SRM-CAM Discord: Mads and other students answer there, and new features are explained first. See Community.
