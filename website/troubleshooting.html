Troubleshooting

Symptom → cause → fix, learned on real boards. Search for what you saw, or open the six that cost the most boards: they come with a live explainer.

The six that cost the most boards

The drill and the cut-out keep stopping, and the job takes far longer

CauseThe bit sits too high in the collet, so the head has to go very low to reach the copper. The mill's Z ends at −55 mm in machine coordinates; the through-cuts of the drill and the cut-out go 1.7 mm below the surface and keep hitting that end.

FixWith the bit on the copper, machine Z must stay above −50. Check it by switching VPanel's coordinates from G54 to Machine, or read the Z in SRM-CAM's bottom bar, which always shows machine Z. Too low: loosen the collet and refit the bit so it sticks out further, then zero Z again (back on G54).

The cut-out ran first, and the board came loose before the traces

CauseVPanel lists the files alphabetically, so _cutout.nc lands above _drill.nc and _traces.nc, and VPanel runs the list from the top. Everything after the cut-out is machined on a board held by four 1.5 mm tabs.

FixAfter Cut › Add, look at the list before Output: move the cut-out to the bottom with the arrows. The list must start with the drill or the traces (the lab prefers the drill first), never the cut-out. The dry run, if you add it, goes at the very top.

Z was set, but the job cuts air, or goes far too deep

CauseZ was set with VPanel on Machine or User. The exported files are NC code and move in G54, so they run from whatever G54 zero the last person left. Machine's origin cannot be moved at all; User is the RML origin, which NC files ignore.

FixSwitch VPanel's coordinate list to G54, lower until SRM-CAM reads Touch, and press Set Origin Point › Z. Leave X and Y at the machine origin. See Zero Z on the copper.

Traces are shorted in some areas and clean in others

CauseThe copper foil is 0.035 mm and the cut 0.15 mm deep, while a clamped sheet bows by about 0.13 mm. Where the sheet dips, a flat cut never gets through the foil.

FixLevel the bed: jog to the first marked point, set the final Z zero there, then Probe over the link; the finished probe switches on Warp the exported cut to this surface. Spots missed on a board already cut: rework them.

✕ marks on the traces: the checks say the spots will be shorted

CauseTwo nets sit closer than the 0.8 mm bit. The cutter physically cannot pass between them, so the gap stays copper whatever the depth.

FixBest: more clearance in KiCad (Board Setup › Net Classes, at least 0.8 mm) or a narrower bit. If the design can't change: Interface › Full, then Isolation traces › Cutting parameters and tick Cut gaps too narrow for the bit, which trims both pads.

The board looks clean, but two nets are shorted

CauseA hair or strand of copper the mill didn't clear, lying across a channel. Burrs from the cut and the sanding do the same.

FixInspect the board closely after sanding, and check with a multimeter on continuity: every connection you want beeps, and no two nets beep. Scrape a strand out along the channel with a knife; a real uncut gap needs rework.

At the machine

Cut far deeper than the trace depth on a screwed-down board

CauseThe extra depth for a board held at points: a quarter of the arch the map shows, capped. With the warp off, the whole range is charged.

FixMake sure the map is applied. If it is still too much, untick Work the extra depth out from the probe map and set Cut deeper by yourself, on Set up the job › The copper. See Holding the copper.

VPanel refuses the file with an error

CauseVPanel's command set does not match the file (.nc needs NC Code, .rml needs RML-1), or a coordinate is outside the machine's travel.

FixSet the command set in VPanel's Setup dialog. For travel, the Off the bed check names the cause; move the job fully onto the bed.

The dry run leaves the copper

CauseThe job is not where the copper is: the sheet's corner on the stage is wrong, or the board was placed off the sheet.

FixStop it: nothing has been cut. Find the copper's corner with the probe and press Set up the job › The copper › Set the corner from the tool, then place the board on the sheet (Centre it on the copper) and export again. Never move the XY origin in VPanel instead.

Wrong depth after a bit change

CauseA new bit sticks out by a different amount, so the old Z zero is wrong for it.

FixRe-zero Z after every bit change and after the flip, with VPanel on G54, and check the machine Z is still above −50. Never re-zero X or Y. The lab's one-bit profile has no bit change at all.

Probing and the link

Connect fails

CauseThe Arduino IDE's Serial Monitor holds the port, the wrong port is picked, or the cable was replugged.

FixClose the Serial Monitor; pick the right port; replug and Machine › Rescan the serial ports. Only one program can hold the port.

A whole column of probe points failed

CauseThey were outside the machine's travel.

FixThe grid is clipped to the reachable copper when it is built; if points still fail, the job itself is off the bed: see the checks.

no touch

CauseThe clip is off the copper, the copper is dirty or oxidised where the bit lands, or the bit started too high above it.

FixReseat the red clip on the copper (it is the only wire: the bit is wired inside the machine), clean the copper, and start the bit a couple of millimetres above the surface.

unstable

CauseA flaky contact.

FixClean the copper and reseat the clip, then probe the failed points again.

“The bit is already touching the copper”

CauseBoth touches descend from where the bit is, so they cannot start on the copper.

FixRaise it a few millimetres with Page Up, then try again.

“No live position yet”

CauseThe grid is measured from where the tool is standing, so the position readout has to be alive first.

FixGive it a moment after connecting, and try again.

A lone spike in the 3D surface

CauseA flaky touch at that point.

FixClear that row and probe it again.

Nothing moves after a STOP

CauseSTOP drops the move in flight and stops the spindle; the bit stays where it is.

FixRaise the bit with Page Up before the next move.

No machine bar, just a sentence

CauseThe machine link runs on Windows only.

FixExport on Linux and send the files from a Windows PC. Your own laptop at the mill works for the link and for VPanel only if it runs Windows.

Panels

“Two boards overlap” and the export refuses

CauseOverlapping boards are one shape and cannot be cut apart.

FixMove one, or Set up the job › Where it sits on the bed › Lay them side by side (4 mm apart) or Butt them together (one shared cut).

A board's side is not in the cut-out

CauseIts edge is on the sheet's edge, so there is nothing to cut there.

FixIf that is wrong, set the sheet's real size and corner on Set up the job › The copper.

The panel does not fit the reachable copper

CauseThe sheet ends before the travel does, or the boards plus a gap are wider than the sheet.

FixMove the sheet, butt the boards, or cut them one after the other.

Double-sided

Top mirrored or offset after the flip

CauseThe board was turned the other way than the plan expects. A fiducial fit cannot catch this.

FixBefore cutting the top, select the top step and jog to a distinctive board hole to check. See Double-sided boards.

“Too far out to cut”

CauseThe measured board is too far from where the plan put it.

FixRe-seat the board and probe again; Find it for me is repeatable. The files are not written under a bad fit without asking.

Setups and the app

“Setup loaded, but … could not be read”

CauseThe Gerber folder moved, or the file is from the first interface with something this one cannot read. It says what.

FixCheck the job before you cut; point it at the folder again.

Can't find the exports or setups

CauseThey live in your Documents.

FixDocuments\SRM-CAM\exports and …\sessions; File › Open the export folder opens it. Dialogs reopen the last folder used.

The window never opens

CauseA startup failure, often the graphics driver.

FixRead Documents\SRM-CAM\gui2.log. On Linux without a GPU driver, run with GERBER2RML_GL=software.
